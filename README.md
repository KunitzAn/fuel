# Fuel

Личный счётчик калорий и КБЖУ — замена FatSecret без его неудобств. PWA на
iPhone, `fuel.kunitcan.online`. Многопользовательское (вход по коду на почту),
но пользуюсь в основном я.

Этот файл — договорённости из планирующего чата. Кода ещё нет, начинаем с
этапа 0 (см. «План по этапам»).

## Идея

- Дневник еды по дням: завтрак / обед / ужин + перекусы между ними
- Еду берём из: своей истории, своих продуктов, своих блюд, общей базы
  (базовые продукты + покупные из Open Food Facts), по штрихкоду
- Если продукта нет — один раз вношу КБЖУ с этикетки, дальше беру из своих
- Цель по КБЖУ с **карб-сайклингом**: в дни тренировок цель растёт по
  заданному правилу (сейчас — за счёт углей), тренировки тянутся с Apple
  Watch через Команды iOS
- Статистика: лента по дням (строками) + графики
- Без ИИ, без веса тела, без воды, без геймификации (серии, сообщество,
  premium — всего этого нет)

## Что бесит в FatSecret (и как делаем иначе)

| FatSecret | Fuel |
|---|---|
| Не считает калории, если ввести только БЖУ | Ккал пустые → при сохранении считаются из БЖУ автоматически; плюс кнопка «= из БЖУ» |
| Свои блюда потом сложно найти | Отдельные вкладки «Продукты» и «Блюда», поиск по каждой букве, свои — выше базы |
| Неверное КБЖУ у готовых продуктов, сложно поправить | Правка продукта из базы создаёт **мою версию**, дальше везде показывается она (с пометкой ✎) |
| Один общий «Перекус/Другое» | Перекусов сколько угодно, после любого основного приёма, со своим названием |

## Стек

Тот же, что в `daylens` — оттуда же копируем каркас.

- **Frontend:** Vue 3 + TypeScript + Vite + Tailwind, иконки `@lucide/vue`
- **PWA:** `vite-plugin-pwa` (Workbox), precache app shell,
  `navigateFallback` — открывается офлайн «с нуля» (подробности почему — в
  README daylens, раздел «Почему PWA»). Сплэш-скрины iOS — так же, как в daylens
- **Локальные данные:** IndexedDB через Dexie — local-first, дневник
  работает без сети (во Вьетнаме связь бывает так себе)
- **Backend:** Cloudflare Pages Functions
- **БД:** Neon Postgres + Drizzle. **Два проекта Neon:**
  - `fuel` — пользователи, дневник, мои продукты/блюда, активность, цели
  - `fuel-catalog` — общий каталог продуктов (импорт OFF + базовые). Отдельно,
    чтобы каталог не съел лимит free tier (0.5 ГБ на проект) у личных данных
- **Email:** Resend (код входа)
- **Хостинг:** Cloudflare Pages, `fuel.kunitcan.online`, деплой из GitHub
- **Тема:** по системной (светлая/тёмная), без переключателя

## База продуктов

Готовой бесплатной базы «российские марки + азиатские + базовые продукты
по-русски» не существует, поэтому три уровня.

### 1. Мои продукты и блюда

Всё, что внесла сама, плюс мои версии продуктов из базы. Живут в Dexie —
находятся мгновенно и офлайн.

### 2. Базовые продукты (seed)

200–400 базовых продуктов на русском: крупы (сухие и варёные), мясо и птица
(сырые и приготовленные), яйца, молочка, овощи, фрукты, масла, орехи,
хлеб и т.п. Значения — из стандартных справочных таблиц, КБЖУ на 100 г.
Список готовит Claude как seed-файл, кладём в `fuel-catalog` с
`source = 'basic'`. Названия так, как их ищут: «Гречка варёная», «Куриная
грудка отварная», «Яйцо куриное».

### 3. Open Food Facts (покупные)

**Поиск по названию — по своей копии, не через живой API.** У живого API
OFF лимит поиска около 10 запросов в минуту, русский поиск слабый, и сам
сервис бывает недоступен (во время планирования лежал с 503).

Разовый импорт среза в `fuel-catalog`:
- Источник — дамп OFF (на момент планирования они публикуют его в Parquet
  на Hugging Face, `openfoodfacts/product-database`; проверить актуальный
  формат и место). Фильтровать удобно через DuckDB локально
- **Страны** (`countries_tags` — «где продаётся», так что импортные товары с
  полок тоже попадут): Россия, Вьетнам, Таиланд, Япония, Южная Корея, Китай,
  Тайвань, Гонконг, Индонезия, Малайзия, Сингапур, Филиппины, Камбоджа, Лаос
- **Только с заполненными** белками, жирами, углеводами на 100 г
  (`proteins_100g`, `fat_100g`, `carbohydrates_100g`); ккал из
  `energy-kcal_100g`, если нет — считаем из БЖУ
- **Только нужные поля:** штрихкод, название, марка, Б/Ж/У/ккал на 100 г,
  страны. Название: `product_name_ru` → `product_name` → любое доступное;
  для поиска храним все варианты названий (ru/en/локальное) в одном
  нормализованном поле
- Оценка объёма — порядка 100–200 тыс. строк, 100–200 МБ с индексами.
  **Проверить реальный размер до заливки**
- Обновление — тем же скриптом раз в пару месяцев (вручную или GitHub Action)

**Штрихкод:** сначала ищем в `fuel-catalog`; если нет — живой запрос к API
OFF (`/api/v2/product/{code}`, обязателен свой `User-Agent`), найденное
сохраняем в каталог. Не нашлось нигде — открываем форму нового продукта
со штрихкодом.

### Мои версии продуктов из базы

Правка продукта из базы → форма с его данными, заголовок «Моя версия» →
сохраняется как **мой продукт** со ссылкой `sourceCatalogId`. Каталог не
меняется (у других пользователей всё как было). В поиске мой вариант
показывается вместо оригинала, с пометкой ✎.

Просто выбор продукта из базы в дневник **не** копирует его в «Продукты» —
он и так будет в «Истории» (со снимком КБЖУ, доступен офлайн).

### Мои продукты — приватные

Что добавил пользователь — видит только он. Общие только базовые и OFF.

## Функционал

### Главный экран — дневник дня

Лейаут как в FatSecret (скрин был в планирующем чате):

```
 [🔍] [📅]                                   [⚙]
 Сегодня
  Пн   Вт   Ср  (Чт)  Пт   Сб   Вс       ← неделя, ✓ = в дне есть записи
                                           свайп по полосе = соседняя неделя
 ─────────────────────────────────────────
    Б         Ж         У       Ккал
  123/120   25/60   224/204⚡  1629/1950   ← факт / цель; ⚡ = цель изменена активностью
 ─────────────────────────────────────────
 ┌ ☀ Завтрак                 416 ккал  ＋ ┐
 │   27,5    4,5    64,3    26%       ⌄ │  ← Б Ж У и доля от ккал дня
 └─────────────────────────────────────┘
 ┌ Перекус                   180 ккал  ＋ ┐  ← только если добавлен
 └─────────────────────────────────────┘
 ┌ ☀ Обед ...                              ┐
 ┌ 🌅 Ужин ...                             ┐
 ┌ 🔥 Потрачено 2 100 · Разница −680   ⟳ ┐  ← ⟳ = подтянуть тренировки
 └─────────────────────────────────────┘
```

- Порядок макросов везде **Б / Ж / У**
- Можно ходить и в прошлые, и в **будущие** дни (📅 — календарь для прыжка
  далеко)
- **Завтрак, обед, ужин — всегда**, даже пустые. Названия фиксированные
- Приём пищи раскрывается по ⌄: список еды (название, граммы, ккал). Тап по
  еде — правка граммов, свайп — удалить
- **Перекусы:** в раскрытом приёме последняя строка «+ перекус после
  завтрака/обеда/ужина». По умолчанию название «Перекус», тап по
  названию — переименовать (вводится каждый раз своё, без списка). После
  одного приёма может быть несколько перекусов — в порядке добавления.
  Пустой перекус исчезает, когда уходишь с экрана
- **Карточка энергии** внизу: потрачено, разница (съедено − потрачено),
  список активностей дня («Силовая 45 мин · 320 ккал», «Прогулка · 150
  ккал»), «+ активность» (ручной ввод), ⟳ — запустить Команду iOS

### Добавление еды

Открывается по ＋ у приёма пищи.

```
 ← Завтрак ▾                          ← можно сменить приём (вкл. перекусы)
 [ 🔍 поиск…                    ][▦]  ← ▦ = сканер штрихкода
 История │ Продукты │ Блюда │ База
 ─────────────────────────────────
 Вчера
   Овсянка «Геркулес»          60 г  ＋
   Яйцо С1                    110 г  ＋
   Кофе с молоком             250 г  ＋
 22 сентября
   …
 ─────────────────────────────────
 [ + Новый продукт / блюдо ]          ← зависит от открытой вкладки
```

- **История** — все приёмы вперемешку, по дням (свежие сверху), внутри дня —
  в том порядке, в каком добавляла
- **Продукты** — мои покупные продукты (с этикеток) + мои версии продуктов
  из базы
- **Блюда** — мои блюда
- **База** — базовые + OFF (серверный поиск)
- **＋ в строке** — добавить сразу, с граммами из прошлой записи этого
  продукта, без окна
- **Тап по строке** — окно ввода граммов

**Поиск — по мере ввода, на каждую букву**, по всем разделам сразу, выдача
**блоками по очереди**:

```
 [ 🔍 грудк                         ][▦]
 История
   Грудка куриная отварная     150 г  ＋
 Продукты
   Грудка ✎ (изменено)                 ＋
 Блюда
   Грудка в сливках                    ＋
 База
   Филе грудки «Петелинка»             ＋
   …
```

- История/Продукты/Блюда — локально из Dexie, мгновенно, офлайн
- База — `GET /api/catalog/search?q=` с debounce ~250 мс и отменой
  предыдущего запроса; без сети блок не показывается
- Подстрока в любом месте названия **и марки**; без учёта регистра;
  `ё` = `е`; запятая/точка не важны
- Один продукт показывается один раз — в самом верхнем блоке, где нашёлся

**Окно ввода граммов** — шторка снизу:

```
 Овсянка «Геркулес»
 на 100 г: Б 12 · Ж 6 · У 62 · 352 ккал
 ┌──────────────┐
 │   60      г  │   ← фокус сразу, цифровая клавиатура
 └──────────────┘
 Б 7,2 · Ж 3,6 · У 37,2 · 211 ккал   ← пересчёт на лету
 [ Завтрак ▾ ]            [ Добавить ]
```

- Подставляются граммы с прошлого раза для этого продукта (во всех
  вкладках); впервые — 100 г
- Только граммы, без порций. **1 мл = 1 г** для жидкостей

### Сканер штрихкода

- В Safari на iOS нет нативного `BarcodeDetector` → полифилл на zxing-wasm
  (npm-пакет `barcode-detector`), камера через `getUserMedia`
- iOS в standalone-PWA может переспрашивать разрешение камеры — это
  ограничение системы, не баг
- Логика поиска — см. «Штрихкод» выше

### Форма продукта

```
 Новый продукт
 Название*        [ Творог 5% «Простоквашино»  ]
 Марка            [                            ]
 Штрихкод         [ 4600000000000        ][▦]
 КБЖУ указаны:    (• на 100 г)  ( на порцию [ 30 ] г )
 Белки*   [ 16  ]   Жиры*  [ 5  ]   Углеводы* [ 3 ]
 Ккал     [ 121 ]  [ = из БЖУ ]
 [ Сохранить ]      [ Сохранить и добавить ]
```

- **«на порцию __ г»** — для азиатских этикеток («Serving size 30 g»):
  вбиваю как на этикетке, храним пересчитанное на 100 г
- **Ккал:** можно вписать с этикетки; кнопка «= из БЖУ»; если пусто при
  сохранении — считаем сами. Если введённое расходится с расчётом больше
  чем на 10% — мягкая подсказка «по БЖУ выходит 121» (не ошибка)
- Числа: принимаем **и запятую, и точку** (`inputmode="decimal"`)
- Б+Ж+У > 100 г на 100 г — предупреждение про опечатку
- «Сохранить и добавить» — сразу окно граммов для текущего приёма
- Форма открывается со штрихкодом, если сканер ничего не нашёл

### Форма блюда

То же без марки и штрихкода, плюс **заметка** — свободный текст («из чего
и в каких пропорциях готовила»). КБЖУ на 100 г я считаю сама при готовке;
заметка в расчётах **не участвует**. Порций нет.

### Правка и удаление

Правка/удаление продукта или блюда **не меняет прошлые дни**: запись в
дневнике хранит снимок КБЖУ на момент добавления. Удаления мягкие
(`deletedAt`), как в daylens.

### Калории из БЖУ

`ккал = Б×4 + Ж×9 + У×4` — везде одна функция.

## Цели и энергия (карб-сайклинг)

### Настройки

```
 Цель по умолчанию (день без активности)
   Белки [ 120 ] г   Жиры [ 60 ] г   Углеводы [ 150 ] г
   = 1 620 ккал                        ← считается из БЖУ, не вводится

 Энергия покоя              [ 1 450 ] ккал

 На каждые 100 ккал активности:
   Б [ 0 ] г   Ж [ 0 ] г   У [ 18 ] г   ≈ 72 ккал   ← подсказка
```

- Плавать может любой макрос в любой пропорции (сейчас только угли,
  потом, например, Б+У пополам). Граммы «на 100 ккал» я задаю сама — в них
  же зашита моя поправка на то, как часы считают калории
- Обычной/бытовой активности в настройках **нет** — если нужно, ввожу её
  вручную как активность
- Минимумов по макросам нет (цель не может уйти ниже дефолтной — прибавка
  только положительная)

### Расчёт на день

```
активность = Σ тренировки с Apple Watch + Σ ручные активности   (ккал)

цель Б = база Б + активность / 100 × Б_на_100
цель Ж = база Ж + активность / 100 × Ж_на_100
цель У = база У + активность / 100 × У_на_100
цель ккал = 4×цель Б + 9×цель Ж + 4×цель У

потрачено = энергия покоя + активность
разница   = съедено − потрачено      (минус = дефицит)
```

- Без синхронизации и ручных записей: потрачено = энергия покоя, цель по
  умолчанию
- **Ручная активность** (название необязательно + ккал) влияет и на
  «потрачено», **и на цель** — так же, как тренировки
- Цель считается **в течение дня**: подтянулись тренировки — цель выросла

### История настроек целей

Изменение настроек действует **с сегодняшнего дня**, прошлые дни остаются со
своими целями. Храним версии настроек с `validFrom`; для дня берём версию с
максимальным `validFrom ≤ дата`.

## Синхронизация тренировок — Команды iOS

У веб-приложений нет доступа к HealthKit, поэтому данные отправляет Команда
iOS (Shortcuts). Apple Watch есть, тренировки с него в Здоровье попадают.

- **Что шлём:** только **тренировки** (не общую активную энергию и не
  энергию покоя — покой берём из настроек). Тренировка: id, тип, начало,
  конец, ккал
- **Эндпоинт:** `POST /api/health/workouts`, `Authorization: Bearer <личный
  токен>`, тело `{ workouts: [...] }` за сегодня и вчера (чтобы добрать
  поздние). Сервер делает upsert по `(userId, externalId)` — повторные
  отправки безопасны
- **Личный токен:** в настройках — показать/скопировать, «выпустить новый»
  (старый перестаёт работать). В БД храним хэш
- **Когда запускается:**
  - автоматизации «Время суток» в приложении Команды — сколько угодно раз в
    день (например 12/16/20/23). Из Fuel расписание менять **нельзя** — оно
    живёт в Командах, поэтому в настройках — пошаговая инструкция
  - автоматизация «Тренировка Apple Watch завершена» (проверить, что триггер
    есть и работает как ожидаем)
  - кнопка ⟳ в Fuel: открывает `shortcuts://run-shortcut?name=Fuel`, Команда
    в конце открывает `https://fuel.kunitcan.online/` — возвращаемся, делаем
    pull, цель пересчитана
- **Статус в настройках:** «Последняя синхронизация: сегодня 20:15 · 2
  тренировки · 540 ккал»
- **Проверить при сборке Команды:** отдаёт ли действие «Найти образцы
  Здоровья → Тренировки» калории тренировки. Если нет — запасной путь:
  активная энергия за интервал каждой тренировки
- Готовую Команду Claude собрать не может — собираем вместе на телефоне по
  инструкции

## Статистика

Две вкладки: **Лента │ Графики**.

### Лента

Одна **строка** на день, листается вниз в прошлое, подгрузка порциями:

```
          Б        Ж       У       Ккал    Потр.  Разн.
 Чт 24   118      52     190     1 780   2 150   −370
         /120     /60    /204⚡   /1 950
 Ср 23   131      48     152     1 640   1 980   −340
         /120     /60    /172⚡   /1 820
 Вт 22   — нет записей —
```

- Шапка прилипает при скролле; единицы — в шапке, не в ячейках
- Под фактом мелко — цель того дня (с учётом активности, по версии
  настроек того дня). Факт подсвечен цветом: в пределах / недобор /
  перебор. Допуск (например ±5%) — решить при реализации
- ⚡ — в этот день цель менялась от активности
- Тап по строке — открыть день в дневнике

### Графики

- Период: Неделя │ Месяц │ 3 месяца, стрелками — соседние периоды
- **Средние в день:** съедено, потрачено, разница, Б/Ж/У. **Итого разница
  за период** в ккал. **Никакого пересчёта в вес** — вес не ведём
- **Калории по дням:** столбики «съедено» + отметка цели дня; под ним —
  потрачено/разница
- **Б, Ж, У по дням:** три маленьких графика, в каждом столбики + отметка
  цели
- Дни без записей и сегодняшний (незаконченный) день в средние не входят

## Модель данных — черновик

`fuel` (Neon) + зеркало в Dexie для всего, кроме служебных таблиц:

```
users, login_codes, sessions     // как в daylens

foods                            // мои продукты и блюда
  id, userId, kind: 'product' | 'dish',
  name, brand?, barcode?,
  protein, fat, carbs, kcal,     // на 100 г
  note?,                         // для блюд — рецепт-заметка
  sourceCatalogId?,              // если это «моя версия» продукта из базы
  lastGrams?,                    // для подстановки в окно граммов
  createdAt, updatedAt, deletedAt

snacks                           // перекусы конкретного дня
  id, userId, date, after: 'breakfast' | 'lunch' | 'dinner',
  name, position, createdAt, updatedAt, deletedAt

entries                          // записи дневника
  id, userId, date,
  meal: 'breakfast' | 'lunch' | 'dinner' | 'snack', snackId?,
  foodId? | catalogId?,          // откуда взяли
  name, brand?,                  // снимок
  protein, fat, carbs, kcal,     // снимок на 100 г
  grams,
  createdAt,                     // порядок в дне и в «Истории»
  updatedAt, deletedAt

activities
  id, userId, date, source: 'watch' | 'manual',
  name?, kcal, externalId?,      // externalId — id тренировки из Здоровья
  startedAt?, durationMin?,
  createdAt, updatedAt, deletedAt

goal_settings                    // версии, см. «История настроек целей»
  id, userId, validFrom,
  baseProtein, baseFat, baseCarbs,
  restingKcal,
  perHundredProtein, perHundredFat, perHundredCarbs,
  createdAt

api_tokens                       // для Команды iOS
  id, userId, tokenHash, createdAt, lastUsedAt, revokedAt
```

`fuel-catalog` (отдельный Neon-проект):

```
catalog_products
  id, barcode?, name, brand?,
  protein, fat, carbs, kcal,     // на 100 г
  source: 'basic' | 'off',
  countries text[],
  search text                    // нормализованные названия+марка: lower, ё→е
  // индекс: GIN pg_trgm по search; уникальный по barcode
```

- Поиск в каталоге: `search ILIKE '%q%'` с сортировкой по `similarity()`,
  `limit 30`; базовые выше OFF
- Все удаления мягкие — нужно для синка
- Суммы по дням считаем на клиенте из `entries` (снимки КБЖУ × граммы / 100)
